# Feature Specification: Mindful Cruise - ADHD 집중 앱

**Feature Branch**: `mindful-cruise-focus-app`  
**Created**: 2024-12-19  
**Status**: Draft  
**Input**: 사용자 설명: "ADHD가 있는 사람들을 대상으로 설정한 시간(최소 15분 최대 2시간)동안 방치하면 상품 추첨을 할 수 있는 티켓을 주는거지 컨셉은 바다를 항해하는 크루즈. 영일만항에서 울릉도까지 400분을 모두 채워야 하선 가능. 울릉도 도착 시 울릉도→영일만항 항로로 자동 전환(왕복 시스템). 실제 항로를 시각적으로 표시하고, 항해 시 크루즈가 바다를 가르며 이동하는 효과 필요. 집중 세션 영상은 현재 크루즈가 바다를 가르는 영상만 구현하되, 향후 울릉도 전경, 크루즈 내부 영상 추가 가능. AI 기능은 프로토타입에서 제외."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 항로 선택 및 집중 모드 시작 (Priority: P1)

ADHD 사용자가 앱을 열고 항로를 선택한 후, 집중 시간을 설정하고 집중 모드를 시작할 수 있어야 합니다. 이는 앱의 핵심 기능으로, 사용자가 목표를 설정하고 집중 활동을 시작하는 첫 단계입니다.

**Why this priority**: 앱의 핵심 가치인 "집중 시간 동안 방치"를 위한 기본 기능입니다. 다른 모든 기능은 이 기능이 완성되어야 의미가 있습니다.

**Independent Test**: 사용자가 앱을 열고, 영일만항→울릉도 항로를 선택하고, 집중 시간을 15분~120분(최대 세션 시간) 사이로 설정한 후 집중 모드를 시작할 수 있는지 확인합니다. 집중 모드가 시작되면 타이머가 작동하고, 크루즈가 바다를 가르며 이동하는 시각적 효과가 표시되어야 합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 앱을 처음 열었을 때, **When** 항로 선택 화면을 확인하면, **Then** 영일만항→울릉도(400분) 항로가 표시되어야 합니다. (이후 울릉도 도착 시 울릉도→영일만항으로 자동 전환)
2. **Given** 사용자가 항로를 선택했을 때, **When** 집중 시간 슬라이더를 조절하면, **Then** 최소 15분, 최대 120분(최대 세션 시간) 사이에서 설정할 수 있어야 하며, 120분을 초과할 수 없어야 합니다.
3. **Given** 사용자가 집중 시간을 설정했을 때, **When** "출항하기" 버튼을 누르면, **Then** 집중 모드 화면으로 전환되고 타이머가 시작되어야 합니다.
4. **Given** 집중 모드가 시작되었을 때, **When** 화면을 확인하면, **Then** 원형 타이머와 남은 시간이 시각적으로 표시되어야 합니다.
5. **Given** 집중 모드가 시작되었을 때, **When** 화면을 확인하면, **Then** 크루즈가 바다를 가르며 이동하는 시각적 효과가 표시되어야 합니다 (배가 앞으로 나아가는 애니메이션). [참고: 향후 확장 시 울릉도 전경, 크루즈 내부 영상 등 추가 가능]
6. **Given** 사용자가 집중 모드를 시작했을 때, **When** 앱을 완전히 종료하려고 하면, **Then** "앱을 종료하면 진행 기록이 사라집니다" 경고 메시지가 표시되어야 합니다.

### User Story 2 - 집중 시간 완료 및 진행도 업데이트 (Priority: P1)

사용자가 설정한 집중 시간을 완료하면, 항로 진행도가 업데이트되고 목적지 도착 여부를 확인할 수 있어야 합니다. 이는 사용자의 노력을 보상하고 동기를 부여하는 핵심 메커니즘입니다.

**Why this priority**: 사용자가 집중 시간을 완료했을 때 즉각적인 피드백과 보상이 제공되어야 지속적인 사용이 가능합니다. 진행도 시스템은 장기적인 동기를 유지하는 데 필수적입니다.

**Independent Test**: 사용자가 30분 집중 모드를 완료하면, 해당 항로의 진행도가 30분 증가하고, 남은 시간이 정확히 표시되는지 확인합니다. 진행도가 100%에 도달하면 알림이 표시되고 재시작 여부를 물어봐야 합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 집중 모드를 시작했을 때, **When** 설정한 시간이 모두 경과하면, **Then** "항해 종료" 상태로 전환되어야 합니다.
2. **Given** 타이머가 0에 도달했을 때, **When** 진행도가 400분(100%)에 도달하지 않았으면, **Then** "하선 확인" 버튼이 아닌 "항해 계속하기" 또는 "중간 하선" 같은 다른 옵션이 표시되어야 합니다.
3. **Given** 타이머가 0에 도달했을 때, **When** 진행도가 400분(100%)에 도달했으면, **Then** 알림이 표시되고 "다시 시작할까요?" 확인 메시지가 표시되어야 합니다.
4. **Given** 타이머가 0에 도달했을 때, **When** 사용자가 5분 이내에 확인을 누르면, **Then** 설정한 시간이 그대로 인정되어 진행도에 반영되어야 합니다.
5. **Given** 타이머가 0에 도달했을 때, **When** 사용자가 5분을 초과하여 확인을 누르면, **Then** 인정 시간이 10%로 감소하고 경고 메시지가 표시되어야 합니다.
6. **Given** 집중 시간이 완료되어 진행도가 업데이트되었을 때, **When** 홈 화면으로 돌아가면, **Then** 선택한 항로의 진행도가 시각적으로 표시되어야 합니다.
7. **Given** 집중 시간이 완료되어 진행도가 업데이트되었을 때, **When** 홈 화면을 확인하면, **Then** 실제 항로 지도에 현재 위치가 비행기 항로처럼 표시되어야 합니다. 영일만항→울릉도 항로일 때는 영일만항에서 울릉도까지의 경로에, 울릉도→영일만항 항로일 때는 울릉도에서 영일만항까지의 경로에 현재 진행도에 따른 위치를 표시해야 합니다.
8. **Given** 항로 진행도가 100%에 도달했을 때, **When** 알림이 표시되면, **Then** "울릉도 도착!" 또는 "영일만항 도착!" 메시지와 함께 재시작 여부를 확인하고, 자동으로 반대 방향 항로로 전환되어야 합니다.

### User Story 3 - 목적지 도착 및 왕복 항로 전환 (Priority: P1)

사용자가 항로를 완주(400분 달성)하면 목적지에 도착하고, 상품 추첨 티켓을 획득한 후 왕복 항로로 전환됩니다. 이는 앱의 핵심 보상 메커니즘으로, 사용자의 장기적인 동기를 유지하고 지속적인 항해 경험을 제공합니다.

**Why this priority**: 티켓 획득은 앱의 핵심 가치 제안입니다. 사용자가 집중 시간을 투자한 결과로 명확한 보상을 받아야 지속적인 사용이 가능합니다. 왕복 항로 시스템은 사용자가 계속해서 항해를 이어갈 수 있게 합니다.

**Independent Test**: 사용자가 영일만항→울릉도 항로를 완주(400분 달성)하면 티켓 1장을 획득하고, 알림이 표시되며, 울릉도→영일만항 항로로 자동 전환되는지 확인합니다. 티켓은 홈 화면에 표시되어야 합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 영일만항→울릉도 항로를 완주(400분 달성)했을 때, **When** 알림이 표시되면, **Then** "울릉도 도착! 티켓 1장을 획득했습니다" 메시지와 함께 티켓 1장을 획득해야 합니다.
2. **Given** 티켓을 획득했을 때, **When** 홈 화면으로 돌아가면, **Then** 티켓 개수가 업데이트되어 표시되어야 합니다.
3. **Given** 항로를 완주했을 때, **When** 보상을 받으면, **Then** "다시 시작할까요?" 확인 메시지가 표시되어야 합니다.
4. **Given** 사용자가 "다시 시작"을 선택했을 때, **When** 확인하면, **Then** 울릉도→영일만항 항로로 자동 전환되고 진행도가 0으로 리셋되어야 합니다.
5. **Given** 울릉도→영일만항 항로로 전환되었을 때, **When** 홈 화면을 확인하면, **Then** 새로운 항로(울릉도→영일만항, 400분)가 표시되어야 합니다.
6. **Given** 울릉도→영일만항 항로를 완주했을 때, **When** 보상을 받으면, **Then** 다시 영일만항→울릉도 항로로 전환되어야 합니다 (왕복 시스템).
7. **Given** 티켓 교환 시, **When** 포인트가 부족하거나 티켓이 0개일 때, **Then** 티켓 개수가 음수가 되지 않도록 검증해야 합니다.

### User Story 4 - 낚시 게임으로 포인트 획득 (Priority: P2)

사용자가 집중 모드 대신 또는 추가로 낚시 게임을 통해 포인트를 획득하고, 포인트로 티켓을 교환할 수 있어야 합니다. 이는 집중 모드 외의 대안 활동을 제공하여 사용자의 선택권을 넓힙니다.

**Why this priority**: 낚시 게임은 집중 모드의 대안 활동으로, 사용자가 지루함을 느낄 때 다른 방식으로 보상을 받을 수 있게 합니다. 또한 포인트 시스템은 추가적인 동기 부여 메커니즘을 제공합니다.

**Independent Test**: 사용자가 낚시 게임을 시작하고, 입질이 왔을 때 버튼을 눌러 물고기를 낚으면 포인트를 획득하는지 확인합니다. 낚시 시간도 항로 진행도에 반영되어야 합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 홈 화면에 있을 때, **When** "낚시하러 가기" 버튼을 누르면, **Then** 낚시 게임 화면으로 전환되어야 합니다.
2. **Given** 낚시 게임이 시작되었을 때, **When** 화면을 확인하면, **Then** 실제 배에서 낚시를 하는 것처럼 시각적 효과가 표시되어야 합니다 (배의 갑판에서 낚시하는 장면).
3. **Given** 낚시 게임이 시작되었을 때, **When** 일정 시간이 지나면, **Then** "입질이 왔다!" 알림이 표시되어야 합니다.
4. **Given** 입질 알림이 표시되었을 때, **When** 사용자가 버튼을 누르면, **Then** 물고기를 낚거나 티켓을 획득할 수 있어야 합니다.
5. **Given** 물고기를 낚았을 때, **When** "획득하기" 버튼을 누르면, **Then** 해당 물고기의 포인트가 추가되어야 합니다.
6. **Given** 낚시 게임을 종료했을 때, **When** 홈 화면으로 돌아가면, **Then** 낚시한 시간이 항로 진행도에 반영되어야 합니다.
7. **Given** 낚시 중 티켓을 발견했을 때, **When** 획득하면, **Then** 티켓 1장이 추가되어야 합니다 (매우 낮은 확률).

### User Story 5 - 포인트로 티켓 교환 (Priority: P2)

사용자가 낚시 게임으로 획득한 포인트를 티켓으로 교환할 수 있어야 합니다. 이는 포인트 시스템의 가치를 높이고 사용자에게 추가적인 보상 경로를 제공합니다.

**Why this priority**: 포인트 시스템이 의미 있으려면 티켓으로 교환할 수 있어야 합니다. 이는 사용자가 낚시 게임에 참여하는 동기를 제공합니다.

**Independent Test**: 사용자가 200 포인트 이상을 보유하고 있을 때, 포인트 상점에서 티켓 1장을 교환할 수 있는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 홈 화면에 있을 때, **When** 포인트 표시 영역을 클릭하면, **Then** 포인트 상점 모달이 열려야 합니다.
2. **Given** 포인트 상점이 열렸을 때, **When** 현재 보유 포인트를 확인하면, **Then** 보유 포인트가 표시되어야 합니다.
3. **Given** 사용자가 200 포인트 이상을 보유했을 때, **When** "교환하기" 버튼을 누르면, **Then** 티켓 1장을 획득하고 포인트가 200 감소해야 합니다.
4. **Given** 사용자가 200 포인트 미만을 보유했을 때, **When** "교환하기" 버튼을 확인하면, **Then** 버튼이 비활성화되어야 합니다.

### User Story 6 - 화면 꺼짐 감지 및 집중 모드 보호 (Priority: P2)

사용자가 집중 모드 중에 화면을 꺼두거나 다른 앱으로 전환하면 이를 감지하고 경고해야 합니다. 이는 앱의 핵심 가치인 "방치"를 보장하는 중요한 기능입니다.

**Why this priority**: ADHD 사용자를 위한 디지털 디톡스 앱의 핵심은 실제로 집중하는 것입니다. 화면을 꺼두거나 다른 앱을 사용하는 것은 앱의 목적에 맞지 않으므로 이를 감지하고 방지해야 합니다.

**Independent Test**: 사용자가 집중 모드를 시작한 후, 브라우저 탭을 전환하거나 화면을 최소화하면 경고가 표시되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 집중 모드를 시작했을 때, **When** 브라우저 탭을 전환하거나 화면을 최소화하면, **Then** 타이머가 일시정지되고 "⚠️ 화면을 켜두세요!" 경고가 표시되어야 합니다.
2. **Given** 타이머가 일시정지된 상태일 때, **When** 사용자가 다시 화면으로 돌아오면, **Then** 타이머가 재개되어야 합니다.
3. **Given** 사용자가 집중 모드 중에 화면을 꺼두었을 때, **When** 시간이 경과하면, **Then** 일시정지된 시간은 진행도에 반영되지 않아야 합니다.

### User Story 10 - 데이터 영속성 (Priority: P1)

사용자가 앱을 닫았다가 다시 열어도 진행도, 티켓, 포인트 등 모든 데이터가 유지되어야 합니다. 이는 앱의 핵심 가치인 "장기적인 동기 부여"를 보장하는 필수 기능입니다.

**Why this priority**: 데이터가 사라지면 사용자가 앱을 지속적으로 사용할 동기가 없어집니다. 데이터 영속성은 앱의 핵심 가치를 보장하는 필수 기능입니다.

**Independent Test**: 사용자가 진행도를 쌓고 티켓을 획득한 후 앱을 닫았다가 다시 열면, 모든 데이터가 그대로 유지되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 집중 모드를 완료하여 진행도를 업데이트했을 때, **When** 앱을 닫았다가 다시 열면, **Then** 진행도가 그대로 유지되어야 합니다.
2. **Given** 사용자가 티켓을 획득했을 때, **When** 앱을 닫았다가 다시 열면, **Then** 티켓 개수가 그대로 유지되어야 합니다.
3. **Given** 사용자가 포인트를 획득했을 때, **When** 앱을 닫았다가 다시 열면, **Then** 포인트가 그대로 유지되어야 합니다.
4. **Given** 사용자가 설정을 변경했을 때, **When** 앱을 닫았다가 다시 열면, **Then** 설정이 그대로 유지되어야 합니다.
5. **Given** localStorage에 저장 공간이 부족할 때, **When** 데이터를 저장하려고 하면, **Then** 에러 처리가 되고 사용자에게 알림이 표시되어야 합니다.

### User Story 11 - 상품 추첨 시스템 (Priority: P1)

사용자가 획득한 티켓을 사용하여 상품 추첨에 참여할 수 있어야 합니다. 이는 앱의 핵심 가치 제안으로, 사용자가 집중 시간을 투자한 결과로 실제 보상을 받을 수 있게 합니다.

**Why this priority**: 티켓을 모을 수 있지만 사용할 곳이 없으면 앱의 핵심 가치가 전달되지 않습니다. 상품 추첨 시스템은 앱의 핵심 가치 제안을 완성합니다.

**Independent Test**: 사용자가 티켓을 보유하고 있을 때, 추첨 화면에서 티켓을 사용하여 추첨에 참여할 수 있는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 티켓을 보유하고 있을 때, **When** 홈 화면에서 추첨 버튼을 클릭하면, **Then** 추첨 화면이 열려야 합니다.
2. **Given** 추첨 화면이 열렸을 때, **When** 보유 티켓 개수를 확인하면, **Then** 현재 보유 티켓 개수가 표시되어야 합니다.
3. **Given** 사용자가 티켓 1장 이상을 보유했을 때, **When** "추첨하기" 버튼을 누르면, **Then** 티켓이 소모되고 추첨 애니메이션이 표시되어야 합니다.
4. **Given** 추첨이 완료되었을 때, **When** 결과를 확인하면, **Then** 당첨 여부와 상품 정보가 표시되어야 합니다.
5. **Given** 사용자가 티켓이 없을 때, **When** 추첨 화면을 확인하면, **Then** "티켓이 부족합니다" 메시지가 표시되어야 합니다.
6. **Given** 추첨 결과가 저장되었을 때, **When** 추첨 이력을 확인하면, **Then** 과거 추첨 이력이 표시되어야 합니다.

### User Story 12 - 사용자 온보딩 (Priority: P2)

사용자가 앱을 처음 실행할 때 앱 사용법을 안내하고 기본 설정을 할 수 있어야 합니다. 이는 ADHD 사용자를 위한 맞춤형 환경을 제공하는 첫 단계입니다.

**Why this priority**: 온보딩은 사용자가 앱을 올바르게 사용할 수 있도록 안내하고, 맞춤형 설정을 통해 사용자 경험을 개선합니다.

**Independent Test**: 사용자가 앱을 처음 실행하면 온보딩 화면이 표시되고, 설정을 완료한 후 홈 화면으로 이동하는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 앱을 처음 실행했을 때, **When** 앱을 열면, **Then** 온보딩 화면이 표시되어야 합니다.
2. **Given** 온보딩 화면이 표시되었을 때, **When** 앱 소개를 확인하면, **Then** 앱의 목적과 사용법이 설명되어야 합니다.
3. **Given** 사용자가 기본 집중 시간을 설정했을 때, **When** 설정을 완료하면, **Then** 선택한 시간이 기본값으로 저장되어야 합니다.
4. **Given** 사용자가 알림 설정을 했을 때, **When** 설정을 완료하면, **Then** 알림 설정이 저장되어야 합니다.
5. **Given** 온보딩을 완료했을 때, **When** 다시 앱을 열면, **Then** 온보딩 화면이 표시되지 않아야 합니다.
6. **Given** 사용자가 온보딩을 건너뛰고 싶을 때, **When** "건너뛰기" 버튼을 누르면, **Then** 기본 설정으로 홈 화면으로 이동해야 합니다.

### User Story 13 - 통계 및 진행 상황 시각화 (Priority: P2)

사용자가 자신의 집중 시간, 완주한 항로, 획득한 티켓 등 전체적인 성과를 시각적으로 확인할 수 있어야 합니다. 이는 사용자의 동기를 부여하고 지속적인 사용을 유도합니다.

**Why this priority**: 통계는 사용자가 자신의 성과를 확인하고 동기를 부여받는 중요한 요소입니다. 시각적 피드백은 ADHD 사용자에게 특히 중요합니다.

**Independent Test**: 사용자가 통계 화면을 열면 일일/주간/월간 집중 시간, 완주한 항로, 획득한 티켓 등이 시각적으로 표시되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 홈 화면에 있을 때, **When** 통계 버튼을 클릭하면, **Then** 통계 화면이 표시되어야 합니다.
2. **Given** 통계 화면이 열렸을 때, **When** 일일 집중 시간을 확인하면, **Then** 오늘 집중한 시간이 표시되어야 합니다.
3. **Given** 통계 화면이 열렸을 때, **When** 주간/월간 통계를 확인하면, **Then** 해당 기간의 집중 시간이 차트로 표시되어야 합니다.
4. **Given** 사용자가 항로를 완주했을 때, **When** 통계 화면을 확인하면, **Then** 완주한 항로 이력이 표시되어야 합니다.
5. **Given** 통계 화면이 열렸을 때, **When** 획득한 티켓을 확인하면, **Then** 총 획득 티켓 개수가 표시되어야 합니다.
6. **Given** 사용자가 연속으로 집중 모드를 완료했을 때, **When** 통계 화면을 확인하면, **Then** 연속 달성 일수(Streak)가 표시되어야 합니다.

### User Story 14 - 알림 시스템 (Priority: P2)

사용자가 집중 시간 완료, 목적지 도착 등 중요한 이벤트에 대해 브라우저 알림을 받을 수 있어야 합니다. 이는 앱을 닫아도 사용자가 중요한 정보를 놓치지 않도록 합니다.

**Why this priority**: 알림은 사용자가 앱을 사용하지 않을 때도 중요한 정보를 전달하여 사용자 경험을 개선합니다.

**Independent Test**: 사용자가 알림 권한을 허용하고 집중 모드를 완료하면 브라우저 알림이 표시되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 앱을 처음 실행했을 때, **When** 알림이 필요한 기능을 사용하려고 하면, **Then** 알림 권한 요청이 표시되어야 합니다.
2. **Given** 사용자가 알림 권한을 허용했을 때, **When** 집중 시간이 완료되면, **Then** 브라우저 알림이 표시되어야 합니다.
3. **Given** 사용자가 알림 권한을 허용했을 때, **When** 목적지에 도착하면, **Then** 도착 알림이 표시되어야 합니다.
4. **Given** 사용자가 알림 설정을 변경했을 때, **When** 설정을 저장하면, **Then** 알림 설정이 저장되어야 합니다.
5. **Given** 사용자가 알림을 끄고 싶을 때, **When** 설정에서 알림을 비활성화하면, **Then** 알림이 표시되지 않아야 합니다.

### User Story 15 - 접근성 개선 (Priority: P3)

ADHD 사용자를 포함한 모든 사용자가 앱을 편리하게 사용할 수 있도록 접근성 기능을 제공해야 합니다. 이는 사용자 경험을 개선하고 더 많은 사용자가 앱을 사용할 수 있게 합니다.

**Why this priority**: 접근성은 사용자 경험을 개선하는 중요한 요소이지만, 핵심 기능이 완성된 후에 구현할 수 있습니다.

**Independent Test**: 사용자가 다크 모드를 활성화하거나 폰트 크기를 조절하면 설정이 적용되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 설정 화면에 있을 때, **When** 다크 모드를 활성화하면, **Then** 화면이 다크 모드로 전환되어야 합니다.
2. **Given** 사용자가 설정 화면에 있을 때, **When** 폰트 크기를 조절하면, **Then** 앱 전체의 폰트 크기가 변경되어야 합니다.
3. **Given** 사용자가 색상 대비를 개선하고 싶을 때, **When** 고대비 모드를 활성화하면, **Then** 색상 대비가 개선되어야 합니다.
4. **Given** 사용자가 키보드 단축키를 사용하고 싶을 때, **When** 단축키를 누르면, **Then** 해당 기능이 실행되어야 합니다.
5. **Given** 스크린 리더를 사용하는 사용자가 있을 때, **When** 앱을 사용하면, **Then** 스크린 리더가 모든 요소를 읽을 수 있어야 합니다.

### User Story 16 - 오프라인 지원 (Priority: P3)

사용자가 인터넷 연결이 없어도 집중 모드와 낚시 게임을 사용할 수 있어야 합니다. 이는 앱의 핵심 기능이 항상 사용 가능하도록 보장합니다.

**Why this priority**: 오프라인 지원은 사용자 경험을 개선하지만, 핵심 기능이 완성된 후에 구현할 수 있습니다.

**Independent Test**: 사용자가 인터넷 연결을 끊고 집중 모드를 시작하면 정상적으로 작동하는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 인터넷 연결이 없을 때, **When** 집중 모드를 시작하면, **Then** 집중 모드가 정상적으로 작동해야 합니다.
2. **Given** 사용자가 인터넷 연결이 없을 때, **When** 낚시 게임을 시작하면, **Then** 낚시 게임이 정상적으로 작동해야 합니다.
3. **Given** 사용자가 오프라인 상태일 때, **When** 앱을 사용하면, **Then** 오프라인 상태임을 알리는 표시가 있어야 합니다.
4. **Given** 사용자가 오프라인에서 데이터를 변경했을 때, **When** 온라인으로 돌아오면, **Then** 변경사항이 저장되어야 합니다.

### User Story 17 - 에러 처리 개선 (Priority: P3)

시스템 오류가 발생했을 때 사용자에게 친화적인 메시지를 표시하고, 가능한 경우 자동으로 재시도하거나 폴백 UI를 제공해야 합니다.

**Why this priority**: 에러 처리는 사용자 경험을 개선하지만, 핵심 기능이 완성된 후에 개선할 수 있습니다.

**Independent Test**: 네트워크 오류가 발생했을 때 사용자에게 친화적인 메시지가 표시되고 재시도 옵션이 제공되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 네트워크 오류가 발생했을 때, **When** 사용자가 기능을 사용하려고 하면, **Then** "네트워크 연결을 확인해주세요" 메시지가 표시되어야 합니다.
2. **Given** 데이터 저장 오류가 발생했을 때, **When** 사용자가 데이터를 저장하려고 하면, **Then** "저장에 실패했습니다. 다시 시도해주세요" 메시지와 재시도 버튼이 표시되어야 합니다.
3. **Given** 예상치 못한 오류가 발생했을 때, **When** 오류가 발생하면, **Then** 전역 에러 바운더리가 오류를 처리하고 폴백 UI를 표시해야 합니다.
4. **Given** 사용자가 재시도 버튼을 클릭했을 때, **When** 재시도하면, **Then** 작업이 다시 시도되어야 합니다.

### User Story 18 - 성능 최적화 (Priority: P3)

앱의 로딩 속도와 실행 속도를 최적화하여 사용자 경험을 개선해야 합니다.

**Why this priority**: 성능 최적화는 사용자 경험을 개선하지만, 핵심 기능이 완성된 후에 최적화할 수 있습니다.

**Independent Test**: 앱의 초기 로딩 시간이 3초 이내인지, 집중 모드 전환이 500ms 이내인지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 앱을 열었을 때, **When** 초기 로딩을 확인하면, **Then** 로딩 시간이 3초 이내여야 합니다.
2. **Given** 사용자가 집중 모드를 시작했을 때, **When** 화면 전환을 확인하면, **Then** 전환 시간이 500ms 이내여야 합니다.
3. **Given** 사용자가 이미지를 로드할 때, **When** 이미지가 표시되면, **Then** 지연 로딩이 적용되어야 합니다.
4. **Given** 사용자가 비디오를 재생할 때, **When** 비디오가 재생되면, **Then** 최적화된 비디오가 로드되어야 합니다.

### User Story 19 - 모바일 반응형 개선 (Priority: P3)

모바일 기기에서도 앱이 완벽하게 작동하고 사용하기 쉬워야 합니다.

**Why this priority**: 모바일 반응형은 사용자 경험을 개선하지만, 핵심 기능이 완성된 후에 개선할 수 있습니다.

**Independent Test**: 모바일 기기에서 앱을 사용하면 모든 기능이 정상적으로 작동하고 터치 인터페이스가 최적화되어 있는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 모바일 기기에서 앱을 사용할 때, **When** 화면을 확인하면, **Then** 레이아웃이 모바일에 최적화되어야 합니다.
2. **Given** 사용자가 모바일에서 버튼을 누를 때, **When** 터치하면, **Then** 터치 영역이 충분히 커야 합니다.
3. **Given** 사용자가 모바일에서 스와이프를 할 때, **When** 스와이프하면, **Then** 스와이프 제스처가 인식되어야 합니다.
4. **Given** 사용자가 PWA로 설치했을 때, **When** 앱을 사용하면, **Then** 네이티브 앱처럼 작동해야 합니다.

### Edge Cases

- **앱 종료 시 데이터 손실**: 사용자가 집중 모드를 시작한 후 앱을 완전히 종료하면 진행 기록이 사라집니다. 이를 경고 메시지로 사용자에게 알려야 합니다.
- **여러 항로 동시 진행 불가**: 사용자는 여러 항로를 동시에 진행할 수 없습니다. 한 번에 하나의 항로만 진행 가능합니다.
- **티켓 개수 검증**: 티켓 개수는 무조건 0 이상이어야 합니다. 교환 시 음수가 되지 않도록 검증해야 합니다.
- **항로 진행도 경계 조건**: 항로 진행도가 100%를 초과할 수 없습니다. 최대 400분까지만 인정됩니다.
- **집중 시간 설정 제한**: 집중 시간 설정은 최대 세션 시간(120분)을 초과할 수 없습니다. 사용자가 더 긴 시간을 원하더라도 최대 120분까지만 인정됩니다.
- **100% 달성 시 알림**: 항로 진행도가 100%에 도달하면 알림을 표시하고 재시작 여부를 확인해야 합니다.
- **400분 미달성 시 처리**: 집중 시간이 완료되었지만 400분에 도달하지 않았을 때는 "하선 확인"이 아닌 다른 옵션(예: "항해 계속하기", "중간 하선")을 제공해야 합니다.
- **브라우저의 자동 재생 정책**: 브라우저의 자동 재생 정책으로 인해 배경 비디오가 재생되지 않을 때의 폴백 처리 (정적 이미지 표시)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 영일만항→울릉도(400분) 또는 울릉도→영일만항(400분) 항로 중 현재 활성화된 항로를 선택할 수 있어야 합니다. 울릉도 도착 시 자동으로 반대 방향 항로로 전환됩니다.
- **FR-002**: 시스템은 사용자가 집중 시간을 최소 15분, 최대 120분(최대 세션 시간) 사이에서 설정할 수 있어야 하며, 120분을 초과할 수 없어야 합니다. 사용자가 더 긴 시간을 원하더라도 최대 120분까지만 인정됩니다.
- **FR-003**: 시스템은 집중 모드가 시작되면 타이머를 시작하고 시각적 피드백(원형 타이머, 남은 시간 표시)을 제공해야 합니다.
- **FR-004**: 시스템은 집중 모드가 시작되면 크루즈가 바다를 가르며 이동하는 시각적 효과를 표시해야 합니다 (배가 앞으로 나아가는 애니메이션). [참고: 향후 확장 시 집중 세션 영상 옵션 추가 가능 - 1. 크루즈가 바다를 가르는 영상(현재), 2. 울릉도 전경, 3. 크루즈 내부 영상]
- **FR-005**: 시스템은 집중 시간이 완료되었을 때, 진행도가 400분(100%)에 도달하지 않았으면 "하선 확인"이 아닌 다른 옵션(예: "항해 계속하기", "중간 하선")을 제공해야 합니다.
- **FR-006**: 시스템은 집중 시간이 완료되었을 때, 진행도가 400분(100%)에 도달했으면 알림을 표시하고 "다시 시작할까요?" 확인 메시지를 제공해야 합니다.
- **FR-007**: 시스템은 집중 시간이 완료되면 5분 이내에 확인하면 설정한 시간을 그대로 인정해야 합니다.
- **FR-008**: 시스템은 사용자가 5분을 초과하여 확인하면 인정 시간을 10%로 감소시켜야 합니다.
- **FR-009**: 시스템은 집중 시간 완료 시 항로 진행도를 업데이트해야 합니다.
- **FR-010**: 시스템은 항로 진행도가 100%에 도달하면 알림을 표시하고 재시작 여부를 확인해야 합니다.
- **FR-011**: 시스템은 항로 완주(400분 달성) 시 티켓 1장을 보상으로 제공해야 합니다 (영일만항→울릉도 또는 울릉도→영일만항 모두 동일).
- **FR-011-1**: 시스템은 울릉도 도착 시 자동으로 울릉도→영일만항 항로로 전환해야 합니다 (왕복 시스템).
- **FR-011-2**: 시스템은 영일만항 도착 시 자동으로 영일만항→울릉도 항로로 전환해야 합니다 (왕복 시스템).
- **FR-012**: 시스템은 티켓 개수를 홈 화면에 표시해야 하며, 티켓 개수는 항상 0 이상이어야 합니다.
- **FR-013**: 시스템은 실제 항로 지도를 표시하고, 현재 진행도에 따른 위치를 비행기 항로처럼 시각적으로 표시해야 합니다. 영일만항→울릉도 항로일 때는 영일만항에서 울릉도까지의 경로에, 울릉도→영일만항 항로일 때는 울릉도에서 영일만항까지의 경로에 현재 위치를 표시해야 합니다.
- **FR-014**: 시스템은 낚시 게임을 통해 포인트를 획득할 수 있게 해야 하며, 낚시 화면에서는 실제 배에서 낚시를 하는 것처럼 시각적 효과를 제공해야 합니다.
- **FR-015**: 시스템은 낚시 게임 시간을 항로 진행도에 반영해야 합니다.
- **FR-016**: 시스템은 낚시 게임 중 매우 낮은 확률(0.003%)로 티켓을 직접 획득할 수 있게 해야 합니다.
- **FR-017**: 시스템은 사용자가 200 포인트로 티켓 1장을 교환할 수 있게 해야 하며, 티켓 개수가 음수가 되지 않도록 검증해야 합니다.
- **FR-018**: 시스템은 화면 전환 또는 최소화를 감지하고 타이머를 일시정지해야 합니다.
- **FR-019**: 시스템은 화면이 다시 활성화되면 타이머를 재개해야 합니다.
- **FR-020**: 시스템은 사용자가 집중 모드를 시작한 후 앱을 완전히 종료하려고 하면 "앱을 종료하면 진행 기록이 사라집니다" 경고 메시지를 표시해야 합니다.
- **FR-021**: 시스템은 여러 항로를 동시에 진행할 수 없도록 해야 합니다. 한 번에 하나의 항로만 진행 가능합니다.
- **FR-022**: 시스템은 사용자의 항로 진행도, 티켓 개수, 포인트를 영속적으로 저장해야 합니다. [NEEDS CLARIFICATION: 현재는 메모리만 사용, localStorage 또는 서버 저장소 필요 여부 확인]
- **FR-023**: 시스템은 항로 완주 후 진행도를 0으로 리셋하고 반대 방향 항로로 자동 전환해야 합니다 (왕복 시스템).
- **FR-024**: 시스템은 항로 진행도가 100%를 초과할 수 없도록 해야 합니다 (최대 400분).
- **FR-025**: 시스템은 사용자의 항로 진행도, 티켓 개수, 포인트, 설정을 localStorage에 영속적으로 저장해야 합니다.
- **FR-026**: 시스템은 앱 시작 시 localStorage에서 데이터를 로드하고, 데이터가 없으면 기본값을 사용해야 합니다.
- **FR-027**: 시스템은 데이터 변경 시 자동으로 localStorage에 저장해야 합니다.
- **FR-028**: 시스템은 localStorage 저장 공간이 부족할 때 사용자에게 알림을 표시하고 에러를 처리해야 합니다.
- **FR-029**: 시스템은 사용자가 티켓을 사용하여 상품 추첨에 참여할 수 있게 해야 합니다.
- **FR-030**: 시스템은 추첨 화면에서 티켓 소모, 추첨 애니메이션, 결과 표시를 제공해야 합니다.
- **FR-031**: 시스템은 추첨 이력을 저장하고 사용자가 확인할 수 있게 해야 합니다.
- **FR-032**: 시스템은 사용자가 앱을 처음 실행할 때 온보딩 화면을 표시해야 합니다.
- **FR-033**: 시스템은 온보딩에서 앱 소개, 기본 집중 시간 설정, 알림 설정을 제공해야 합니다.
- **FR-034**: 시스템은 온보딩 완료 여부를 저장하고, 완료한 사용자에게는 다시 표시하지 않아야 합니다.
- **FR-035**: 시스템은 통계 화면에서 일일/주간/월간 집중 시간을 차트로 표시해야 합니다.
- **FR-036**: 시스템은 통계 화면에서 완주한 항로 이력, 획득한 티켓 총 개수, 연속 달성 일수(Streak)를 표시해야 합니다.
- **FR-037**: 시스템은 브라우저 알림 API를 사용하여 집중 시간 완료, 목적지 도착 알림을 제공해야 합니다.
- **FR-038**: 시스템은 알림 권한을 요청하고, 사용자가 알림을 켜고 끌 수 있게 해야 합니다.
- **FR-039**: 시스템은 다크 모드, 폰트 크기 조절, 색상 대비 개선, 키보드 단축키, 스크린 리더 지원을 제공해야 합니다.
- **FR-040**: 시스템은 집중 모드와 낚시 게임이 오프라인에서도 작동하도록 해야 합니다.
- **FR-041**: 시스템은 오프라인 상태를 감지하고 사용자에게 알려야 합니다.
- **FR-042**: 시스템은 네트워크 오류, 데이터 저장 오류 등에 대해 사용자 친화적인 에러 메시지를 표시하고 재시도 옵션을 제공해야 합니다.
- **FR-043**: 시스템은 전역 에러 바운더리를 제공하여 예상치 못한 오류를 처리해야 합니다.
- **FR-044**: 시스템은 이미지 지연 로딩, 코드 스플리팅, 비디오 로딩 최적화를 적용해야 합니다.
- **FR-045**: 시스템은 모바일 기기에서 터치 인터페이스를 최적화하고, 화면 크기별 레이아웃을 조정해야 합니다.
- **FR-046**: 시스템은 PWA 지원을 고려하여 오프라인에서도 앱을 사용할 수 있게 해야 합니다 (선택사항).

### Key Entities *(include if feature involves data)*

- **Route (항로)**: 항로 ID, 이름, 방향(영일만항→울릉도 또는 울릉도→영일만항), 총 소요 시간(분, 400분), 최대 세션 시간(분, 120분), 설명, 색상, 출발지 좌표, 목적지 좌표
- **RouteProgress (항로 진행도)**: 항로 ID별로 누적된 집중 시간(분), 최대 400분, 현재 활성 항로 방향
- **RouteMap (항로 지도)**: 실제 항로 경로 좌표 배열, 현재 위치 표시용
- **Ticket (티켓)**: 상품 추첨에 사용되는 티켓 개수 (항상 0 이상)
- **Point (포인트)**: 낚시 게임으로 획득한 포인트, 티켓 교환에 사용
- **FocusSession (집중 세션)**: 시작 시간, 설정된 시간(분, 최대 120분), 완료 여부, 인정된 시간(분), 배경 영상 타입 (현재: 크루즈가 바다를 가르는 영상, 향후: 울릉도 전경, 크루즈 내부 영상 추가 가능)
- **Fish (물고기)**: 물고기 ID, 이름, 희귀도, 티켓 가치, 포인트 가치
- **Raffle (추첨)**: 추첨 ID, 티켓 소모 개수, 추첨 날짜, 당첨 여부, 상품 정보
- **Statistics (통계)**: 일일 집중 시간, 주간 집중 시간, 월간 집중 시간, 완주한 항로 수, 총 티켓 개수, 연속 달성 일수(Streak)
- **UserSettings (사용자 설정)**: 기본 집중 시간, 알림 설정, 다크 모드, 폰트 크기, 색상 대비, 온보딩 완료 여부

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 앱을 열고 30초 이내에 항로를 선택하고 집중 모드를 시작할 수 있어야 합니다.
- **SC-002**: 사용자가 집중 모드를 완료하면 100%의 경우 진행도가 정확히 업데이트되어야 합니다.
- **SC-003**: 사용자가 항로를 완주(400분 달성)하면 100%의 경우 티켓 1장을 획득하고 알림이 표시되며, 자동으로 반대 방향 항로로 전환되어야 합니다 (왕복 시스템).
- **SC-004**: 사용자가 화면을 전환하면 100%의 경우 타이머가 일시정지되어야 합니다.
- **SC-005**: 사용자가 5분을 초과하여 확인하면 인정 시간이 정확히 10%로 감소해야 합니다.
- **SC-006**: 사용자가 낚시 게임을 통해 포인트를 획득하면 100%의 경우 포인트가 정확히 추가되어야 합니다.
- **SC-007**: 사용자가 200 포인트 이상을 보유하고 있을 때 티켓 교환이 100% 성공해야 하며, 티켓 개수가 음수가 되지 않아야 합니다.
- **SC-008**: 항로 진행도가 100%에 도달하면 100%의 경우 알림이 표시되고 재시작 여부를 확인해야 합니다.
- **SC-009**: 집중 시간 설정이 최대 세션 시간(120분)을 초과할 수 없어야 하며, 초과 시도 시 최대 120분까지만 인정되어야 합니다.
- **SC-010**: 집중 시간이 완료되었지만 400분에 도달하지 않았을 때는 "하선 확인"이 아닌 다른 옵션이 표시되어야 합니다.
- **SC-011**: 실제 항로 지도에 현재 위치가 비행기 항로처럼 시각적으로 표시되어야 하며, 현재 활성 항로 방향에 따라 경로가 표시되어야 합니다 (영일만항→울릉도 또는 울릉도→영일만항).
- **SC-012**: 집중 모드 시작 시 크루즈가 바다를 가르며 이동하는 시각적 효과가 표시되어야 합니다.
- **SC-013**: 낚시 게임 시 실제 배에서 낚시를 하는 것처럼 시각적 효과가 표시되어야 합니다.
- **SC-014**: 사용자가 앱을 종료하려고 할 때 진행 기록 손실 경고가 표시되어야 합니다.
- **SC-015**: 사용자의 진행도, 티켓, 포인트 데이터가 앱을 재시작해도 유지되어야 합니다.
- **SC-016**: 사용자가 티켓을 사용하여 추첨에 참여하면 100%의 경우 추첨이 정상적으로 진행되어야 합니다.
- **SC-017**: 사용자가 앱을 처음 실행하면 100%의 경우 온보딩 화면이 표시되어야 합니다.
- **SC-018**: 통계 화면에서 일일/주간/월간 집중 시간이 정확하게 표시되어야 합니다.
- **SC-019**: 사용자가 알림 권한을 허용하면 집중 시간 완료 시 100%의 경우 알림이 표시되어야 합니다.
- **SC-020**: 다크 모드, 폰트 크기 조절 등 접근성 기능이 즉시 적용되어야 합니다.
- **SC-021**: 오프라인 상태에서도 집중 모드와 낚시 게임이 100% 정상 작동해야 합니다.
